# ديربي الحارة ⚽

**الإصدار 0.4 — ملعب كامل وتحكم أسهل ودوري الشلة.**

لعبة متصفح عربية من **تصميم أحمد شاكر**. نسخة أولى تجريبية، برسومات Canvas أصلية وشخصيات خيالية، من دون مكتبات تشغيل أو ملفات من شبكة خارجية.

## جديد في 0.4

- الملعب يملأ مساحة العرض؛ القوائم والنتائج تظهر فوقه. يتحول العرض إلى أفقي على الهاتف، مع زر ملء الشاشة وقفل الاتجاه عندما يدعمه المتصفح.
- الوضع السهل افتراضيًا: سحب للحركة والقفز، وزر تسديد كبير بتوجيه مساعد. السحب اليدوي والأزرار الإضافية متاحان.
- اختيار مهارتين قبل كل مباراة، وتحذير تجميد يمكن تفاديه؛ صد الصاروخ يبدد سرعته.
- نتيجة مفصلة: الأهداف والتسديدات والتصديات والتمريرات والمخالفات وأفضل لاعب.
- غرفة ثابتة وسجل انتصارات، ودوري فردي من 2 إلى 6 لاعبين: كل واحد يقابل الباقي، والمنتظرون يشاهدون. مباريات الفرق حتى 3v3 متاحة في الغرف الودية.

## الموجود

- 13 شخصية: شاكر، عاطف، فوزي، صلاح مشرف، طرفة، جرجس، أبو آدم، شاهين المالكي، عبده، أبو أنس، طه، النمس، بكر.
- اللعب ضد الكمبيوتر: 1v1، 2v2، 3v3؛ زملاؤك الإضافيون يتحكم بهم الكمبيوتر.
- غرف حقيقية حتى 6 لاعبين، رابط دعوة وكود، اختيار الفريق، جاهزية وإكمال الأماكن بالكمبيوتر.
- مباريات 90 ثانية، احتساب أهداف ووقت على الخادم، إعادة مباراة، وتحدي أول فريق يفوز بمباراتين.
- سحب مباشر في ثلثي الملعب اليسار للحركة، وسحبة لأعلى للقفز؛ رفع الإصبع يوقف الحركة.
- اسحب في الثلث اليمين أو من زر التسديد للتصويب، ثم ارفع الإصبع للتسديد؛ معاينة مسار وقوة التسديدة وحركة رجل وأثر للكرة. يمكن التحرك والتصويب بإصبعين معًا.
- أوامر القفز والتسديد لها أرقام تمنع تكرار تنفيذ إيماءة واحدة أثناء مزامنة الشبكة.
- ذكاء كمبيوتر يتمركز جهة مرماه ويتوقع سقوط الكرة، ويستخدم تسديدة ساقطة عند وجود مدافع. الكمبيوتر الموجود مع لاعب بشري يمرر ويساند بدل تسجيل أهداف تلقائية.
- تصادمات محدودة دون إضافة دفع متكرر، ومدى فعلي للتسديد أمام اللاعب، واحتساب الهدف بعد عبور الكرة كاملة خط المرمى.
- كيبورد ولمس متعدد، صوت اختياري، ملء الشاشة، وتخزين ملفات الأوفلاين عبر Service Worker على HTTPS.

## المهارات والانضباط

كل لاعب يختار مهارتين فقط قبل المباراة، وله استخدام واحد لكل منهما، والكمبيوتر يخضع لنفس الحدود. الوقت محسوب بثواني اللعب ويتوقف أثناء الاحتفال بالأهداف.

| المهارة | الأثر | المدة |
|---|---|---|
| التجميد | تحذير مرئي لمدة ثانية؛ يستطيع الخصم القفز أو الابتعاد 90 وحدة لتفاديه. حماية 5 ثوانٍ بعد انتهاء التجميد | ثانيتان |
| الصاروخ | التسديدة التالية الناجحة بسرعة أكبر؛ لا يضيع على ضربة في الهواء | يجب التسديد خلال 5 ثوانٍ |
| تكبير مرمى الخصم | يزيد ارتفاع المرمى من 160 إلى 220 في الرسم والفيزياء | 7 ثوانٍ |
| تصغير مرمى الفريق | ينقص ارتفاع المرمى إلى 105 | 7 ثوانٍ |

الانتظار المشترك بين المهارات 8 ثوانٍ. نفس التأثير لا يتراكم على المرمى؛ إذا اجتمع التكبير والتصغير فالأثران يجتمعان حسابيًا. الأهداف لا تعيد تعبئة الاستخدامات أو تمسح البطاقات؛ المباراة الجديدة تفعل ذلك.

زر «افتكاك» ينفّذ تدخلًا قصيرًا. التدخل من الخلف أو على خصم بعيد عن الكرة مخالفة. أول مرتين تنبيه؛ الثالثة أصفر وإيقاف ثانيتين؛ الرابعة آخر تنبيه؛ الخامسة أصفر ثانٍ وطرد لبقية المباراة. يفصل بين احتساب المخالفات ثانيتان لتجنب احتساب التلامس المتكرر عدة مرات. طرد آخر لاعب يعني خسارة اعتبارية، ويستخدم تحدي الثلاثة الفائز الاعتباري حتى لو كان متأخرًا في النتيجة وقت الطرد. تضييع تسديدة أو عدم لمس الكرة بضربة بعيدة دون تدخل على الخصم ليس مخالفة.

ضغطة التسديد العادية تساعد على التصويب ناحية مرمى الخصم؛ السحب للتصويب اليدوي. الأرقام 1 و2 للمهارتين، وL للافتكاك. واجهة المهارات تعرض الاستخدامات والمدة والانتظار والحكم والعقوبات. الواجهة الحالية تجريبية وتحتاج تجربة لعب فعلية لضبط توازن القدرات.

## تشغيل محلي

يتطلب Node.js 24 أو أحدث بسبب استخدام node:sqlite في خادم التطوير. لا تحتاج npm install.

```bash
npm run dev
```

ثم افتح http://localhost:3000. قاعدة التطوير مؤقتة في الذاكرة؛ الغرف تنتهي بإعادة تشغيله. الإنتاج يستخدم Cloudflare Worker وD1. لا تنشر خادم التطوير على الإنترنت.

```bash
npm run build
npm test
npm run validate
```

## النشر على GitHub Pages

واجهة اللعبة الجاهزة للنشر موجودة في هذا المجلد، والكود الكامل مع الخادم والاختبارات في `source/`.

ملف `config.js` يوجّه الغرف إلى الخادم المنشور: https://derby-alhara-shaker.animatedpeace1.chatgpt.site . GitHub Pages يستضيف الواجهة فقط؛ الغرف تعتمد على استمرار عمل هذا الخادم.

للتطوير المحلي، ادخل إلى `source/` ثم شغّل `npm run dev` باستخدام Node.js 24 أو أحدث. شغّل `npm run build` قبل `npm test`. إعداد الاستضافة داخل المصدر قالب بلا هوية نشر أو مفاتيح؛ عند نقل الخادم إلى استضافة أخرى يلزم تجهيز Worker وD1 وتعديل `API_BASE` في الواجهة.

عند تحديث الواجهة من المصدر، شغّل `npm run build` ثم انسخ محتويات `source/github-pages/` إلى مجلد اللعبة هذا. لا تغيّر ملفات الموقع الرئيسية في جذر المستودع.

## بنية المشروع

- `public/engine.js`: الفيزياء المشتركة، الزمن والأهداف وذكاء الكمبيوتر.
- `public/render.js`: رسم الملعب والشخصيات.

- `worker/api.js`: API الغرف. لا يقبل أهدافًا أو إحداثيات من اللاعب؛ يقبل أوامر التحكم فقط.
- `drizzle/`: ترحيل قاعدة البيانات.

- `tests/`: اختبارات المحرك والغرف والتزامن والفرق.

## حدود النسخة

- المزامنة الحالية HTTP polling بطلب واحد جارٍ لكل لاعب، مع إرسال عاجل عند تغير التحكم وفاصل 70ms بين دورات التحديث. توجد توقعات فورية لحركة اللاعب المحلي وتصحيح من الخادم، واستيفاء بصري للبقية، وليست WebSocket. هذه بنية نسخة تجريبية، ولا ندّعي تحملها أعدادًا كبيرة أو تأخيرًا منخفضًا على كل الشبكات. رفع القدرة العامة يحتاج اختبار حمل ونقل حلقة المباراة إلى خادم WebSocket/Durable Object مناسب.
- لا توجد مطابقة عشوائية أو حسابات أو متجر أو دردشة أو لعب محلي لشخصين بكيبورد واحد في هذه النسخة.
- اللاعب المنقطع يتوقف بعد 900ms من غياب المدخلات، ويمكنه الرجوع بنفس المتصفح مع الاحتفاظ بتخزينه المحلي. في اللوبي ينتهي مكانه بعد 60 ثانية، وتنتقل إدارة الغرفة للاعب نشط عند غياب صاحبها. أسماء اللاعبين داخل اللعبة لا تعني توثيق هوية.
- كود الغرفة وسجل الانتصارات والدوري محفوظون في D1. الرجوع بنفس الجهاز يستعيد الهوية المحفوظة. بعد غياب جميع التحديثات أكثر من دقيقة تُلغى المباراة غير المكتملة ويعود اللوبي، ويمكن استكمال جدول الدوري. قاعدة التطوير المحلية وحدها مؤقتة.
- لا ادعاء بخلو اللعبة من الأخطاء؛ يلزم اختبار ميداني على أجهزة وشبكات مختلفة، خاصة 3v3 على الجوال.
